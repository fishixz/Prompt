ROCHASYSTEM

Plataforma privada de comunicação do Rocha Roleplay

Implementação de WhatsApp + Chamadas de Áudio

---

0. INSTRUÇÃO PRINCIPAL

Você está trabalhando na construção do RochaSystem, uma infraestrutura privada pertencente ao servidor Rocha Roleplay.

O objetivo deste projeto é criar uma plataforma centralizada responsável, inicialmente, pelos seguintes sistemas:

- WhatsApp do celular do Rocha Roleplay;
- mensagens em tempo real;
- contatos compartilhados;
- chamadas de áudio;
- chamadas telefônicas normais;
- chamadas de áudio do WhatsApp;
- WebSocket;
- WebRTC;
- autenticação de clientes CEF;
- persistência de dados;
- API de integração;
- sistema de sessões;
- notificações relacionadas às comunicações;
- documentação completa da API e da integração.

IMPORTANTE

Este projeto NÃO deve ser tratado como um simples site visual.

O objetivo é construir uma infraestrutura backend real, segura, persistente, escalável e preparada para ser consumida pelo CEF integrado ao launcher/APK do Rocha Roleplay e posteriormente pela gamemode SA-MP/Pawn.

A interface web existente, caso exista, deve ser utilizada quando fizer sentido, mas o foco principal deste trabalho é criar uma infraestrutura sólida para o celular do jogo.

11. CRIAÇÃO DE CHAMADA

A API deverá permitir algo equivalente a:

Com:

  "target": "123456"
}

ou:

{
  "type": "PHONE",
  "target": "123456"
}

O formato final pode ser adaptado.

O backend deve:

1. autenticar o solicitante;
2. identificar o jogador real;
3. validar o número;
4. encontrar o destinatário;
5. verificar se o destinatário pode receber chamadas;
6. verificar se já existe chamada conflitante;
7. criar o registro da chamada;
8. gerar um ID único;
9. notificar o destinatário;
10. iniciar o processo de sinalização.

51. CONCORRÊNCIA

Considerar situações como:

- dois jogadores ligando simultaneamente;
- usuário recebendo duas chamadas;
- mesma mensagem sendo enviada duas vezes;
- WebSocket reconectando;
- evento duplicado;

52. DUPLICAÇÃO DE EVENTOS

WebSocket pode receber eventos repetidos em determinadas condições.

O cliente não deve criar duas mensagens ou duas chamadas visuais apenas porque recebeu o mesmo evento duas vezes.

Usar IDs únicos e deduplicação.

- configurações relacionadas;
- chamadas/histórico quando aplicável.

79. BANCO VS REDIS

PostgreSQL

Dados permanentes.

Redis

Dados temporários/cache.

Storage

Arquivos.

WebSocket

Eventos em tempo real.

WebRTC

Áudio em tempo real.
